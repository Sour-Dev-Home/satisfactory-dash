- 2026-09-26 — ADR-0035 PR: the nightly backup can upload to an S3-compatible store that is not AWS (Backblaze B2). New optional `BACKUP_S3_ENDPOINT` (`backend/src/platform/backup/backup.ts`, `.env.example`): empty means plain AWS S3 with exactly the same `aws s3 cp` arguments as before; set, it must be an `https://` URL with no credentials, is reduced to its origin, and is passed as `--endpoint-url` after the profile. A refusal names the variable but never echoes the value. `runbooks/backups.md` gains the Backblaze section: the owner's account, bucket (Object Lock at creation, Governance 30 days), lifecycle (hide at 30 days, delete hidden after 7), the upload-only and read-only application keys, the `satis-backup-b2` profile, and the cutover (manual run, restore rehearsal from B2, switch the task, S3 read-only for 37 days, then delete the bucket and the `satis-backup` IAM user). The privacy page's backups row now reads "Backblaze stores encrypted backups for up to 37 days" (the owner approved this wording), with the date bumped; the privacy outline matches. Tests cover the unset, valid and refused endpoint cases and the argument order.
