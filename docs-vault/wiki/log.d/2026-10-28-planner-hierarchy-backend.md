- 2026-10-28 — Backend (ADR-0061 build PR 2, planner factory hierarchy): the designation routes store and check parents.
  - **Migrations (expand-only):** `1792368000000_planner_designation_parent` adds a nullable `parent_id` to `map.factory_designations` with a foreign key on `(server_id, parent_id)` to the same table, `ON DELETE RESTRICT` (Decision 7), so a parent is always on the same server. `1792454400000_planner_designation_empty_parent` widens the members CHECK from 1..1000 to 0..1000 under the same name (a `-- contract:` line says why that drop is safe).
  - **Writes:** create and replace check the whole resulting set under the existing server row lock (`FOR NO KEY UPDATE`), in `services/designationHierarchy.ts`: a parent that is not there is 409 `designation_stale`, then `designation_cycle` (a self-parent too), `designation_depth` (more than 3 levels, for the moved designation and its whole subtree), `designation_shape` (no members and no children). A replace writes inserts parents first, then updates in place, then deletes. A put in place without `parentId` keeps the parent and null moves it to the top level. `PUT` never changes the parent. The PR 1 guard (`refuseNestingUntilServed`) is gone.
  - **DELETE:** a deleted designation's children move up to its own parent (a write to each, so revision + 1), and an ancestor left with no members and no children is deleted too, in the same transaction. The audit event adds `reparentedIds` and `removedParentIds`. Recorded in ADR-0061 as a dated note.
  - **Concurrency:** a parent deleted by another write is seen as gone under the lock, so the next write naming it is a clean 409 `designation_stale`, never a foreign-key 500. DB tests race a create and a move against a delete of the parent.
  - **Graph:** each designated factory carries `parentDesignationId` (null for top level and automatic factories). Matching is unchanged: a route test compares the graph with and without parents.
