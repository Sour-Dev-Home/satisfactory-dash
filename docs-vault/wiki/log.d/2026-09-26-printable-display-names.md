- 2026-09-26 — Contract (#198): a server's display name must be printable text. `DisplayNameSchema` (`packages/shared/src/serverManagement.ts`, now exported with `NON_PRINTABLE_IN_NAME`) refuses control characters (Unicode Cc), format characters (Cf: the bidirectional overrides and isolates that make text read as something else, zero-width characters, the byte-order mark, the soft hyphen), line and paragraph separators (Zl, Zp), and surrogate, private-use and unassigned code points, after trimming. It applies to create, update and rename alike. Letters in any script, digits, marks, punctuation, symbols, emoji and plain spaces are fine. A second exported rule, `LOOKALIKE_IN_NAME`, also refuses invisible-looking fillers (Hangul fillers U+115F/1160/3164/FFA0, Braille blank U+2800, U+034F, U+17B4/17B5), any space other than the plain space (no-break, em, ideographic and the like), and four or more stacked combining marks; accents and emoji variation selectors still pass. The 64-character limit now counts characters, not UTF-16 units. The servers file loader (`gameserver/serversFile.ts`) uses the same schema, so `import-servers` cannot bypass the rule. Consequence: an emoji joined with the zero-width joiner (a Cf) is refused; the single-character form is accepted. The display name is shown to every member and put in alert messages, so it must not be able to spoof or reorder text. Existing stored names are not migrated (the check applies to what is entered from now on); `import-servers` takes its names from the operator's own file and is unchanged.
