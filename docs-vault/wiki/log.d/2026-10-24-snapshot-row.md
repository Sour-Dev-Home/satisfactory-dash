- 2026-10-24 — ADR-0052 PR 2: the last snapshot of an agent server survives a backend restart. New `telemetry.latest_snapshots` (expand-only migration, one upserted row a server: status, power, factory, the auto-pause reading, reachable, unreachable_since, last_received_at; no players column). A `LatestSnapshotWriter` worker upserts it at most every 5 minutes and only when something changed, at once on a reachability change, and once on graceful shutdown (2 s bound); the upsert only replaces an older-or-equal `last_received_at` and only for a live server (ADR-0054 D3.5). At startup the row is loaded once (reads wait up to 2 s) and served stale until the agent reports. A factory over 2,000,000 bytes is stored as NULL with one warn per crossing. The table joins `DELETE_HISTORY`. `privacy.html` now says the player count's latest reading is one cached copy, replaced by each new reading and deleted with the server, and adds the matching "How long it's kept" line (wording approved by the owner, 2026-10-24); player names are still never stored.
