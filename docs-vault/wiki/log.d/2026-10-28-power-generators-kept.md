- 2026-10-28 — Backend (ADR-0058 Sprint S4-B, generators once per read, the contract from #807): an agent's `power.generators` is now derived at ingest (`deriveGenerators` in `snapshotDerive.ts`: explicit fields, each fuel or supplement item's `unit` from the backend's catalog as an amount, `items` or `m3`) and kept by `LatestSnapshotStore` as `{ list, readAtMs }` per server, apart from the stored power part, which each power part replaces whole. A read replaces the list only when its normalised `observedAt` is newer than the kept one's, so a late or retried snapshot cannot put an older list back; a power part without `generators` keeps it. The power response carries `generators` and `generatorsReadAt` (ISO UTC), both or neither, while the read is at most 3 × `factorySeconds` old (`STALE_AFTER_INTERVALS`), and through unreachable snapshots by the same age rule. A new session or the game clock going backwards (where the power chart resets) drops the list before the snapshot is recorded, so a read in that same snapshot is kept and an older one is refused. The list is not persisted (ADR-0052): after a restart it is absent until the next read. The polled path and the FRM agent never carry generators (unchanged). Tests in `agentSnapshotStore.test.ts`, `agentIngest.test.ts`, `snapshotDerive.test.ts`, `powerService.test.ts` and `agentTelemetry.test.ts`.
