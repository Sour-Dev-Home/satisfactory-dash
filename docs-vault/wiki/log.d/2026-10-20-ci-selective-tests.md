- 2026-10-20 — Pull-request CI now runs only what a change touches (owner's ask): `scripts/ci-select.mjs` maps the changed files to workspaces, adds every workspace that depends on them (package.json plus imports by package name), and adds the inputs a workspace reads from outside its folder (captured responses, the load kit, the frontend's tokens for the server manager, `LICENSE`). A reusable `changes.yml` workflow runs it for `ci.yml`, `e2e.yml`, `image.yml` and `compose.yml`: `verify` always runs (log fragment, script tests) but lints, typechecks, tests and builds only the selected workspaces; the frontend e2e, server-manager e2e, image, compose and load-smoke jobs run only when their workspace is selected. Pushes to `main`, setup changes (workflows, lockfile, package.json files, test configs, the lint plugin, the selector) and unmapped paths run everything; if the selector fails, every job runs. `scripts/ci-select.test.mjs` fails on a new workspace, Playwright suite or top-level path that isn't mapped, and on a workspace file that names an outside path no rule selects it for.
