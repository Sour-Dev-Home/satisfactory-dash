- 2026-10-15 — Terraform part 2 for the AWS move (ADR-0034, #408): the ECS Fargate service with the cloudflared sidecar. New `infra/aws/ecs.tf`: a cluster with Container Insights off; one ARM64 task, 0.5 vCPU / 1 GB, awsvpc, with two essential containers: `backend` (image `var.backend_image`, which must be a `@sha256` digest and has no default; `HOST=127.0.0.1`; no port mapping; a `node -e` health check fetching `http://127.0.0.1:3001/api/health/ready`, since the image has no curl) and `cloudflared` (2026.10.1 by digest, the same pin as `compose.yaml`, which a static test keeps equal; `dependsOn` backend `HEALTHY`; `TUNNEL_URL=http://127.0.0.1:3001`; metrics on loopback). The service runs one task with a public IP for egress in the public subnets and the inbound-free task group, no load balancer, the deployment circuit breaker with rollback, and `wait_for_steady_state`; deploys stop the old task before starting the new one (0/100%), since ADR-0010 assumes one backend. `iam.tf`: the execution role (trusted by `ecs-tasks` for this account only) reads exactly the parameters the task injects, all under `/satis/prod/`, and writes its two log groups; there is no task role, no managed policy and no access key. The backend gets its four required secrets, plus any of the six optional ones listed in `backend_optional_secrets` (SSM can't hold an empty value); `backend_environment` carries plain settings and refuses `HOST` or an SSM name. `logs.tf`: one log group per container, 14 days.
