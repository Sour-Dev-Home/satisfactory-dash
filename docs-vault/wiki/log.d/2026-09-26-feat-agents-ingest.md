- 2026-09-26 — ADR-0031 PR 5a: the backend side of the edge agent. New `agents` module and schema (migration `1790899200000_agents`: `enrollment_codes`, `agent_credentials`, only SHA-256 hashes stored, purged with a removed server). Owner routes under `/api/servers/:serverId`: `POST /agent/enrollment-codes` (10 minutes, single use, drops the previous code; for a server the backend reaches directly, only the operator), `GET /agent`, `DELETE /agent` (revoke). Agent API at `/agent/v1`, outside `/api`: `POST /enroll` (one guarded UPDATE spends the code; unknown, used and expired are the same `enrollment_code_invalid`; in the same transaction the server becomes an 'agent' server and its stored tokens are deleted; 10 attempts a minute per address) and `POST /snapshots` (Bearer credential, every failure the same 401; gzip accepted with the cap on the DECOMPRESSED size, verified by a gzip-bomb test that answers 413, which settles the `[NEEDS VERIFICATION]` in the brief; about 5 a second per credential; bodies never logged). A snapshot feeds what the pollers feed (alert observation board, durable history, power chart) through `createAgentTelemetryServices`; the agent's `observedAt` counts only within a minute of arrival. Live reads of an agent server serve the last snapshot with its own `observedAt`, stale after three of that part's intervals, and 503 `upstream_unreachable` before the first snapshot or when the agent reports the game unreachable. Auto-pause of an agent server is read-only (`not_editable`) until the command PR (5b). The generated authorization tests now cover the three agent routes; only `GET /commands/:commandId` stays exempt until 5b. `createApp` parses JSON only under `/api` now, and the agent API parses its own bodies.
