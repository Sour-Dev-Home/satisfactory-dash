- 2026-10-27 — #728 cause 11 (Phase 1 step 6), planner nodes of kind "other": the conveyors layer is read every 10 minutes while getFactory is read every 30 s, and a rebuilt belt or machine gets a new id, so a belt end can name a machine the latest factory read no longer has. Two parts, no contract change. (1) A changed factory building set now reads conveyors sooner. The local poller (`backend/src/modules/map/services/localWorldPoller.ts`) gets `observeFactoryBuildings(ids)`, fed by every factory read telemetry already makes (`observeFactoryReads` wraps `getFactoryBuildings` in `server.ts`); the edge agent's `WorldReader.observeFactoryBuildings` is fed by each sampled snapshot's factory (`agentRunner.ts`). A sha256 of the sorted id set is compared with the last one; the first set is a baseline and an unchanged set does nothing. On a change the conveyors read runs at once, or 60 s after its last read began (`CONVEYORS_NUDGE_MIN_GAP_MS`), so never more than once a minute; a change during an in-flight read gets one more read after it, and the 10-minute schedule restarts from the nudged read. A nudge never starts a poller that is not running (only the leader runs them). (2) The production graph adds a note, code `staleConveyorEnds`, when conveyor ends name machines (`machine` end kind, which getFactory always returns) that no factory building matches: "N machines on the conveyor data are missing from the latest factory read: conveyor data is older than the factory read and refreshes within 10 minutes." Notes are plain strings the client shows as is, so the planner page shows it with no frontend change.
