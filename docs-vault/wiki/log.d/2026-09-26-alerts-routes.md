- 2026-09-26 — ADR-0027 PR 7b, the alerts API routes (the contract is PR 7a, `packages/shared/src/alerts.ts`). Thirteen routes under `/api/servers/:serverId/alerts/...`, mounted after the servers router so its membership check covers them: every GET for any member, every other method (`POST .../test` included) owner/admin only. `alerts/routes/alerts.ts` validates bodies and queries with the shared schemas and answers with a FIXED message on failure (never the schema's issues), and calls an `AlertsService` interface (so the generated authorization tests stub it); `alerts/services/alertsService.ts` is the logic and `alerts/repositories/apiRepository.ts` the SQL, every statement scoped by the server's public id (a rule id from another server matches nothing). Rules: create only `production_below_target`, at most 50 rules per server and one per item (the server row is locked during a create, so a race cannot pass either), a PATCH's `item` is `rule_item_immutable` and the rest is validated with a per-kind update schema then again with the engine's own params schema (presets are tunable, never deletable: `preset_disable_only`). Destination: `PUT` reuses `parseDiscordWebhookUrl`, the sealing and the destinations repository, re-enables, and a refusal is `webhook_invalid` with a `reason` and never the URL; `PATCH` enables or disables ('manual', pending deliveries given up); `DELETE`; `POST .../test` is rate-limited to 5 a minute per user and honours the kill switch (`delivery_off`). Log: `before` is at most 18 digits with no leading zero (the shared regex is tightened so it always fits a bigint), `limit` 1 to 100, `nextBefore`. Status: `deliveryEnabled`, `mutedUntil` and the firing alerts of enabled rules from `alert_state` (cheap to poll). Mute: at most 7 days ahead (`mute_invalid`). Every write is one transaction with its audit event (`alerts.rule.created/updated/deleted`, `alerts.destination.set/updated/removed/tested`, `alerts.muted/unmuted`), ids and codes only. Platform: `ApiFailure` takes an optional stable `reason` that reaches the error envelope (anything that is not a short lowercase code is dropped), and `deliveryRepository` gains `disableDestinationIn` (the same statements on a connection already in a transaction) and `updated_at` in the destination summary. Shared, additive: `windowMinutes` is an integer, and `ServerSummary` gains an optional `role` (owner, admin, viewer; a UX hint), which `GET /api/servers` fills from the membership query it already runs. The generated authorization tests now cover all 13 (a viewer's write is a 403) and the temporary exemption from PR 7a is gone. Tests: HTTP behaviour and the never-in-a-log capture tests for the webhook URL, the pure patch and mute logic, the role per user, `reason`, and a real-Postgres suite (CI only) for create, patch, delete, the cap, the race, IDOR across servers, the destination flow, paging, status, mute and the audit trail. `runbooks/alerts.md` documents it.
