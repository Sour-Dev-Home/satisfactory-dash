- 2026-10-19 — ADR-0037 build step 3 (#446): the background metrics are recorded at their sources. The power and factory pollers record `satis.poller.cycle.duration` and `satis.poller.lag` (from the planned tick to the stored snapshot), labelled with the server's public id and the group `power` or `factory`; the agent snapshot route records `satis.agent.ingest.lag`, received-at minus the agent's `observedAt` ("apparent" lag, clock skew included, clamped at 0); the history writer counts `satis.history.rows_written` per table for the rows that actually landed; the alert engine records `satis.alerts.evaluation.duration` per tick and `satis.alerts.fire.lag` per stored fire (the tick time minus the power or factory reading that triggered it; the timer-driven `server_unreachable` and `agent_offline` have no such reading and record none). The registry's `group`, `table` and `kind` labels are now closed sets. Sources record through `createBackgroundRecorder` (platform/metrics), which drops and logs once any failure, into a process-wide aggregator that `createSeriesFlushWorker` drains with the request aggregator, so `server.ts` is unchanged. The pollers record only with a server public id, which `createTelemetryServices` passes when there is a database.
