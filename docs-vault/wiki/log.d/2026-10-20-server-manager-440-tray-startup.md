- 2026-10-20 — Server manager 4/4 (#440, ADR-0040): the app now lives in the tray. The icon is green running, amber starting or stopping, red stopped or crashed (`server-manager/src/tray.ts`, colours from the dashboard's ok/warn/bad tokens), with a tooltip naming the state and a menu of Open, Start, Stop, Restart, Quit and "Stop server and quit". Closing the window hides it (a one-time note says so), and only one instance runs. Quit leaves the server running, now spawned detached, and the next launch adopts it (`supervisor.adopt(pid)`, `leftoverServer.ts` `findLeftover`/`watchPid`) only when the recorded pid still runs the configured `FactoryServer.exe` (its command line, read with a fixed PowerShell or `ps` call), so a reused pid is never taken over. "Stop server and quit" does the clean stop first and stays open when it can't save. Start with Windows (off by default) adds or removes a per-user login item through `app.setLoginItemSettings`, and only when flipped; under the e2e switch it is a file fake, so tests never register one. New runbook `runbooks/server-manager.md`, with window screenshots in `assets/server-manager/` from `npm run screenshots -w server-manager` against the fakes.
