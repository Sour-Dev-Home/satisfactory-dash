- 2026-09-26 — ADR-0032 step 2, the first UX budget: `frontend/e2e/tab-switch.spec.ts` switches Power → Factory → Overview → Power with every API endpoint answering after a different delay (100-600 ms) and fails any switch above CLS 0.02, with motion on and off, at 1440 and 390 px. Shifts right after the click count too (the browser's CLS skips them as "recent input", which is exactly when the staged pop-in happens); each shift's moved elements are printed to the CI log. Measured before the fix: 0 on every switch except Factory on mobile with motion off, 0.078, the machine table jumping 95 px when "Since yesterday" landed above it (the page fade had hidden it with motion on). Fix, reworked to the architect's review (a transition must never delay data): "Since yesterday" reserves a fixed-height box in every state (loading, error, content), sized by new tokens `--spacing-since-yesterday-phone/-mid/-wide` (192/304/236 px). From 640 px wide the box fits its fullest content (3 drops, 3 rises); on a phone it fits the common states and longer lists scroll inside it (the owner's call). `FactoryView` reveals on the factory read plus at most a 300 ms grace for "Since yesterday", so the live table never waits on the 7d read, which can take up to the backend's 5 s timeout. The grace applies only when the factory itself had to load: on a tab switch the factory is usually cached (the Overview reads it), and the page then shows at once, because a late reveal after the grace pushed the footer off a phone screen (CLS 0.071). The reveal stays latched per server. The spec's report now lists each shift and API response by ms after the click. Production history's loading state, below the table, now has its loaded panel's shape, so revealing before its read lands no longer pushes the footer off a phone screen. The spec gains a slow-history variant (the 7d read at 3 s). No `staleTime` or prefetch was needed to meet the budget; prefetching the other tabs when idle stays an option for speed.
