- 2026-10-15 — Backend images for the AWS move (ADR-0034, #404). `backend/Dockerfile` now builds two targets for linux/amd64 and linux/arm64: `runtime` (still only `server.cjs`) and a new `ops` image (the tsx scripts, `backend/migrations`, the PostgreSQL 18 client, age and the AWS CLI) that runs `db:init`, `db:migrate` and `backup` by command. The build stage runs on `$BUILDPLATFORM`, and the ops image's `node_modules` are reinstalled there with the target CPU's native binaries, so arm64 never runs `npm ci` under emulation. `HOST` now defaults to `127.0.0.1`: cloudflared shares the backend's network namespace (Fargate awsvpc, compose `network_mode: "service:backend"`), so `clientIp.ts`'s loopback rule still holds. Both images carry the RDS global CA bundle (`backend/rds-global-bundle.pem`) at `/etc/ssl/rds/global-bundle.pem` for `sslmode=verify-full`. The new `image.yml` workflow builds both images on every PR, boots them against a `postgres:18` service (db:init, db:migrate, then 200 from `/api/health/ready` within 60 s), and on main pushes `:main` and `:<sha>` to GHCR and checks both platforms with `imagetools inspect`. The owner makes the two GHCR packages public once after the first push; `GITHUB_TOKEN` cannot change package visibility.
