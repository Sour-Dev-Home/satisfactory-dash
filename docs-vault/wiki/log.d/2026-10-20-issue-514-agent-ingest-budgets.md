- 2026-10-20 — #514 (ADR-0045 M10, E3, O4): per-credential ingest budgets on the agent API, and auth limits that can't lock out valid agents. The agent-auth limiters now count only FAILED authentications (60 a minute per network, 6,000 for the process; an attempt is counted before its lookup and refunded when it authenticates or the database is down), and a credential that authenticated in the last 15 minutes skips them (still looked up every time, so revocation is immediate), so junk from many addresses no longer gets every agent a 429. Snapshots per credential are a token bucket of 150 then 0.6 a second (three times the 5 s cadence, room for the agent's 120-snapshot queue); decompressed snapshot bytes per credential are 32 MB then 4 MB a minute (a real agent sends about 250 KB; the bytes are charged from express.json's `verify`, a credential in debt is refused before its body is read, and a 413 is charged the cap); command polls and results have their own bucket (30, then one every 2 s); a second open long-poll of a credential ends the first with an empty list. `SNAPSHOT_MAX_BYTES` stays 5 MB (about 440 bytes a building in the contract fixture, so about 11,000 buildings). New counter `satis.agent.refused` (labels `server`, `unknown` before auth, and `status` 400/401/413/415/429). `platform/tokenBucket.ts` is new and `UserRateLimiter` gains `refund`. `runbooks/agents.md` lists every agent API limit. No contract change.
