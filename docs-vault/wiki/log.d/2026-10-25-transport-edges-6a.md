- 2026-10-25 — ADR-0055 PR 6a: the planner draws transport edges. A new pure module, `telemetry/services/logisticsEdges.ts`, turns the stored `trainRoutes` layer into `transports` (mode `train`): each train's timetable is walked cyclically, and a loading platform sends the items both it and each later unloading platform name (platform inventory, or the belts in and out of the platform's node) until the train returns to the loading station; one edge per (platform node, platform node, item), `carriers` counting the distinct trains, `routeName` "A to B". A timetable name that matches two stations (compared after trimming) or none makes no edge and one note each (`duplicateStationName`, `unknownTimetableStop`). Every Dimensional Depot uploader gets a `depot` edge per item it receives to one virtual `Dimensional Depot` node (`role: "depot"`, no site). A train edge's rate is the downstream supply it serves, `estimated`, and only when it is the sole transport bringing that item to the node; nothing reads the unverified `TransferRate` family. The route reads the layer through `map/index.ts` (`readTrainRoutes`: null on a missing, skipped, truncated or invalid row) and the response sets `logistics` to `present` or `notRead`. No contract change (PR 1 already carried the fields); drones and trucks are PR 12.
