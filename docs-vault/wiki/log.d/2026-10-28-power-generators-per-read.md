- 2026-10-28 — Contract (ADR-0058 Sprint S4-B, generators once per read; owner chose option (a) on 2026-10-28): the mod sends `power.generators` only on the snapshot in which it read them, at the factory cadence (`factorySeconds`, today 30 s), not with every 5 s power part, so about 1,000 generators do not spend the snapshot byte budget. On the agent input (`AgentPowerSchema`), present means a read that replaces the last list (`[]` = read, none found) and absent means "no new read; keep the last list"; the read time is the snapshot's own `observedAt`, so no input field is added. The power response (`PowerSchema`) gains optional `generatorsReadAt` (ISO 8601 UTC, response-only, a sender's is dropped), present exactly when `generators` is. The backend (a later PR) keeps the last list per server and serves it until the read is older than 3 × `factorySeconds`, and drops it on a new session; then both fields are absent. Descriptions in `power.ts` and `agent.ts` and a dated section in ADR-0058 record the rules. Tests in `packages/shared/test/agent.test.ts`. Additive (ADR-0007).
