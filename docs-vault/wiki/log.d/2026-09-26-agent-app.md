- 2026-09-26 — Edge agent (ADR-0031 PR 6): the agent program is built, as the new npm workspace `agent/` (`@satisfactory-dash/agent`, one esbuild file `dist/agent.cjs`, Node 22). Commands: `set-tokens` (the game's tokens at a HIDDEN prompt, never argv or environment), `check` (one game read over loopback, counts and codes only), `enroll <CODE> --url <https://backend>` (refused before the tokens are set, because enrolling deletes the backend's stored tokens row), `run`, `status`, `forget-credential`. Secrets (the agent's credential, the game's API and FRM tokens) are stored ONLY as Windows DPAPI CurrentUser blobs through PowerShell `ProtectedData`, the plaintext only on stdin, with real round-trip tests on Windows; a store that cannot be unprotected fails loudly (exit 3). The HTTP client requires https (http only for localhost), never follows a redirect, times out every request, retries transient failures with jittered exponential backoff into a bounded queue that drops the oldest, and stops on a 401 (exit 2). It sends raw readings only, conformed to the input bounds, with `settings.autoPause` each status cadence only when the game is reachable; commands are de-duplicated by id until their expiry and reported as codes. Logs are JSON lines, a file per UTC day, 7 days kept, codes and counts only (enforced at runtime, with a secret scrubber). A permanent failure (a rejected credential, an unreadable store) writes a `halted.json` marker and exits with its code once, then every later start says why and ends with success, so a Scheduled Task that restarts on failure does not loop; `resume` clears it. Response bodies are counted as they stream (a header cannot lie past the cap), a hand-edited store cannot point the game token at a public host, at most 20 commands per poll run, and enrolling proves DPAPI works before the one-time code is spent. Boundary tests keep the agent importing only node, zod, shared and game-adapter. The architecture model now shows the agent as built, and the runbook `runbooks/agent-app.md` covers setup order, the Scheduled Task logon-type trap (an S4U task has no DPAPI key [NEEDS VERIFICATION on the owner's build]) and troubleshooting.
