- 2026-09-26 — Fix (#298): `isTransientConnectionError` (`backend/src/platform/db/errors.ts`) now calls a dual-stack `AggregateError` transient if ANY attempt was (it was: every attempt). On Windows a closed port answers `EACCES` on `::1` and `ECONNREFUSED` on `127.0.0.1` (observed with a closed port; the aggregate's own code is the first attempt's), so a refused connection to `localhost` was classified fatal: startup would not retry while Postgres boots, and a runtime outage would be a 500 instead of a 503. A plain `EACCES` and an aggregate with no transient attempt stay fatal; the startup reason names the transient inner code. This also makes the three `*.db.test.ts` tests that failed only on the Windows dev machine pass. `DATABASE_URL` examples (`backend/.env.example`, `runbooks/database.md`, `runbooks/backups.md`, the `db:init` and `db:migrate` script comments) now use `127.0.0.1` instead of `localhost`, with one line on why; production already did.
