- 2026-09-26 — ADR-0031 PR 5b: commands to an edge agent, and the `agent_offline` alert. Migration `1790985600000_agent_commands` (run `db:migrate` first): `agents.commands` (type `set_auto_pause`, a boolean target, status pending/sent/succeeded/failed/expired, a result CODE from a fixed vocabulary, 60 s expiry) and `agent_offline` in `alerts.rules.kind`. The auto-pause PUT of an agent server now creates a command and answers `202` + `{ command }` (a `local` server keeps `200`; ADR-0031 amendment 1 records where the 202 applies), refused as `not_editable` when no agent is enrolled and as `rate_limited` beyond 5 open commands. `GET /agent/v1/commands?waitSeconds=0..25` is the agent's long-poll: an in-process notifier answers it the moment a command exists (it subscribes before it looks, so no wake-up is lost, at most 3 waiters per server), it returns only that credential's server's commands, and it stops when the agent hangs up. `POST /agent/v1/commands/:commandId/result` takes `{ ok, code? }` only for that server's own commands (an unknown id and another server's are the same `command_not_found`; after the 60 s, `command_expired`; a retry is accepted and changes nothing). The snapshot answer's `commandsPending` is real. `GET /api/servers/:serverId/commands/:commandId` (members) shows a command's status, an open command past its expiry reading as `expired` before the sweeper writes it; the sweeper (every 15 s) expires and purges finished commands after 7 days. Reading an agent server's auto-pause gives the last value the agent confirmed (`pending` while one is on its way); before the first confirmed change it is unknown, because the snapshot has no such field (a contract change for later). `agent_offline` (no snapshot for `offlineSeconds`, default 120, at least 60) is seeded as a preset only for agent servers, measured from the later of the last snapshot and the backend's start, and speaks through a paused or unreachable game; it goes through the same kill switch and shadow week. Saving or editing a local connection now drops that server's unspent enrolment codes (closes the stale-permission window the security review noted). The authorization tests no longer exempt any scoped endpoint. New runbook `runbooks/agents.md`: after a revoke the server stays an agent server with no data, and the only way back is enrolling again.
