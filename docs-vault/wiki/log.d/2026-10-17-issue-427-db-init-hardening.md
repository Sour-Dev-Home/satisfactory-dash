- 2026-10-17 — `db:init` hardening from the AWS security review (#427, findings 4 and 6; #217). `backend/src/platform/db/admin.ts`: before trusting "the admin already holds SET on `satis_migrator`", a non-superuser admin looks in `pg_auth_members` for a SET grant on the migrator that it granted to itself (the temporary grant an earlier run failed to revoke) and revokes it; if that revoke fails, `db:init` stops with an error naming `REVOKE satis_migrator FROM "<admin>"` to run by hand. A SET membership someone else granted is left alone. `CREATE/ALTER ROLE ... PASSWORD` now sends a SCRAM-SHA-256 verifier computed in the client (4096 iterations, a random 16-byte salt, the password SASLprepped as node-pg does), so the plaintext never reaches the server and a failing statement it logs cannot leak it. New cases in `nonSuperuserAdmin.db.test.ts`: the leftover removed, a foreign grant kept, the manual-revoke error, no password in any statement sent, `pg_authid` holding verifiers, login with the password (and refusal of a wrong one), and a password SASLprep changes.
