- 2026-10-25 — ADR-0056 PR 4: the operator metrics endpoint's `alerts` section is built. The alerts module exports `alertQualitySummary(db, nowMs)` (`repositories/alertQualityRepository.ts`, query name `alerts.qualityByMonth`): one read of `alerts.alert_events` through `alert_events_at_idx` for the current and two previous UTC calendar months (the log keeps 90 days, so the oldest month may be partial). Only `fired` and `resolved` rows are paired, per alert (server, kind, subject), with `lead()`: a fired row followed by a resolved row has a resolve time; one followed by another fired, or by nothing, has none. Per month and kind it returns `fired`, `flaps` (resolved within 300 s, inclusive; ADR-0056 Q4's labelled stand-in for false alarms until ADR-0036 D4) and the median resolve seconds (`percentile_cont`, `null` when none resolved), with no server id, subject or summary. The metrics service composes it (`no_data` when empty) and the architecture test gains the edge `metrics -> alerts` (alerts never imports metrics). No migration, no contract change.
