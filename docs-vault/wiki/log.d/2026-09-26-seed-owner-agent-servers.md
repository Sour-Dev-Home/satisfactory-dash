- 2026-09-26 — Fix (#267): at startup `loadDatabaseServers` now seeds the operator as owner of servers reached through an agent too (it did so only for servers with a connection row). It adds the owner only when the server has none; an existing owner is never replaced (the one-owner unique index turns the insert into a no-op) and an operator who is already a non-owner member keeps that role. `listAgentServers` also returns the internal `serverId`. The old unit test that asserted "no owner is seeded for an agent server" is replaced by tests for the new behavior, and `loadAgentServersOwner.db.test.ts` proves it against Postgres (ownerless gets the operator, idempotent with one audit row, another owner untouched, an existing viewer role untouched). Why it matters: routes answer 404 to a non-member, so an ownerless agent server was unreachable for everyone, the operator included.
