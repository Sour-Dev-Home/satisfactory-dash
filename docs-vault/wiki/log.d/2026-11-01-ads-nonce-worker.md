- 2026-11-01 — ADR-0021 amendment 3, build step 2: a Cloudflare Worker (`frontend/worker/index.ts`) now runs in front of the main site's HTML pages (`run_worker_first`: `/*` minus `/assets/*` and every static entry of `public/`; the demo site has no Worker). Each HTML response gets a fresh 128-bit nonce on every script and script preload (HTMLRewriter), the security headers from `worker/securityHeaders.ts` (a test keeps it identical to `public/_headers`, which still serves the static files and `vite preview`), no ETag and `Cache-Control: private, no-cache`; anything else reaching the Worker (the `/privacy.html` redirect, a 304) keeps its status and body and gets today's headers. The ads switch `vars.ADS_ENABLED` is `"false"`, so the CSP sent is exactly today's; the ads-on policy (Google's strict `script-src`, E1) exists but is not yet used, and its other directives are step 4's. Cloudflare's docs captured in `raw-sources/cloudflare-workers-assets-worker-2026-11-01.md`. Checked in workerd before shipping (`wrangler dev --local`): the first run would not start, because workerd treats every named export of the entry module as an entrypoint, so `worker/index.ts` now exports only its handler (the logic is in `worker/handle.ts`, and a test keeps the entry to one export). Then, against the real runtime and the real build: with the switch off, `/` and `/app/*` carry today's CSP and headers, every script and modulepreload has a nonce that differs per request, `/ads.txt` is served as a static file, and `/privacy.html`'s redirect keeps HSTS and the CSP; with the switch on, the CSP's `script-src` carries the same nonce as the page, and `_headers` does not override it.
