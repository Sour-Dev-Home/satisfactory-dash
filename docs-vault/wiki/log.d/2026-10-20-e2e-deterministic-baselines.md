- 2026-10-20 — Screenshot regeneration is now deterministic (issue #503). Unrelated baselines changed on every `update_snapshots` run because Chromium antialiases rounded corners differently from run to run: 5 to 24 pixels, one to six colour levels apart, a different screenshot each time (the clock, fonts, transitions and Chromium rasteriser flags were each tried and none removed it), far under the 50-pixel tolerance, yet `--update-snapshots=all` rewrote every PNG. `.github/workflows/e2e.yml` now regenerates with `--update-snapshots=changed`, which writes only screenshots that fail the tolerance or are missing, so a real change is still captured and noise is not. Two regenerations on the same commit change no files. The `ship-workflow` skill no longer needs `--only` for this.
