- 2026-10-20 — Operator abuse response (#516, ADR-0045, ADR-0046): `npm run admin -- disable-user <user-id>` sets the account to disabled, revokes its sessions and the agent credentials (and unspent codes) of the live servers it owns in one transaction, `enable-user` undoes it, `remove-server <public-id>` is the full delete of any server from the CLI (the HTTP remove 404s for a non-member) and `list-servers` prints every live server with ids and numbers only; each writes an audit event (ids and counts only). Removing a server now also clears `map.world_layers` and `alerts.push_optins`, and reviving a removed id runs the same clean-up again, so a re-created id starts empty even if a write raced the removal (a push opt-in now locks the server row). A database test compares the tables that reference `servers.servers` with the code's delete list, and the migration `purge_removed_server_leftovers` deletes the leftovers of servers removed earlier. New runbook `runbooks/abuse-response.md` (find the server, remove it, disable the owner, what to re-apply after a restore), linked from the index and `database.md`.
