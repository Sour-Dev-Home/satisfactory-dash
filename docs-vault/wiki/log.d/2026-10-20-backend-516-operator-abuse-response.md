- 2026-10-20 — Operator abuse response (#516, ADR-0045): `npm run admin -- disable-user <user-id>` sets the account to disabled and revokes its sessions in one transaction, `enable-user` undoes it, and each writes an audit event (ids and a count only). Removing a server now also clears `map.world_layers` and `alerts.push_optins`, so a re-created id starts empty; a database test fails when a new table references `servers.servers` without being added to the clean-up, and the migration `purge_removed_server_leftovers` deletes the leftovers of servers removed earlier. New runbook `runbooks/abuse-response.md` (find the server, remove it, disable the owner, what to re-apply after a restore), linked from the index and `database.md`.
