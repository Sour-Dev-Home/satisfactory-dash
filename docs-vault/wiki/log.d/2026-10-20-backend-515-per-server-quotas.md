- 2026-10-20 — Per-server quotas for history and alerts, and a fair alert outbox (#515, ADR-0045 M11/M12), so one server's agent, honest or forged, can't fill the database or delay other servers' alerts. History: each power sample records at most 64 circuits (lowest ids), and each item sample records every item in the item catalog plus at most 64 the catalog doesn't know (`telemetry/services/historyQuota.ts`, applied in `BufferedHistoryRecorder` for agent and polled servers). The sizes come from the measured tier-6 save: 1 circuit and 49 items, all in the catalog. Excess rows are dropped, counted (`satis.history.rows_dropped{server,table}`) and logged once per server per hour (`HISTORY_QUOTA_EXCEEDED`). Live views aren't affected. Alerts: a power rule tracks at most 64 circuits, and a gone circuit's state is deleted once it is ok again (`alerts.deleteStates`), so states can't pile up. A server logs at most 120 alert events in any hour, counted from the alert log; the excess is neither stored nor sent (`satis.alerts.events_dropped{server}`, `ALERT_EVENT_QUOTA_EXCEEDED`). The outbox claim is round-robin by server: every server's oldest due row goes before any server's second, and a server's own order stays due time then event order. One evaluation's events now get ids in the evaluator's order (`WITH ORDINALITY`). No migration (the existing `alert_events_server_at_idx` and `outbox_due_idx` serve the new queries) and no contract change. Runbooks: `history.md` (the caps, plus a query that ranks servers by row count for `rds-free-storage-low`), `alerts.md` (the per-server limits), `agents.md` (a pointer).
