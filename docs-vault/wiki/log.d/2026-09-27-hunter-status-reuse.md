- 2026-09-27 — The fresh-eyes/test-hunter status now survives a rebase or a merge from main when the PR's own changes are unchanged (#340, the owner's call; design approved by the architect). A session posts it with `npm run hunter-status -- "<summary>"`, which appends a fingerprint of the PR's own diff (`fp:<12 hex>`: `git patch-id --verbatim` of the diff from the merge-base with main, `--binary --no-renames`). The new `fresh-eyes-reuse` workflow (`pull_request_target` on synchronize, same-repo PRs only, main's script, the PR fetched as objects only) re-posts the success on the new head as "reused from <full sha>, fp:<fp>" when the fingerprint matches. It trusts only a success created by the owner's account; a reuse is re-checked back to that original, one hop. Anything else posts nothing, so the hunter runs again.
