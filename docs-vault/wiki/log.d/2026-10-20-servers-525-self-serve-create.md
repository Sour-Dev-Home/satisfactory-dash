- 2026-10-20 — Servers: self-serve agent server creation, shipped dark (#525, ADR-0046 task 3). `POST /api/servers/agent` (`{ displayName }`, task 1's contract) lets any signed-in active account create an `agent` server with a backend-generated 20-character base32 id, no host, tokens or connection test, and itself as owner, in one transaction under the server-management advisory lock: caps C1 (servers per account, default 2), C3 (never-enrolled per account, default 1; "ever enrolled" comes from the agents module through the composition root) and C2 (live self-serve total, default 25), a plain INSERT (never the reviving upsert), the owner membership and a `server.created` audit row with `detail: { via: "self_serve" }`; the runtime gets the server's agent entry after the commit. A cap answers 409 `server_limit_reached`; C5 (5 creations per account per 24 h, in memory, refused creates not counted) answers 429. The operator's account is exempt from every cap. `SELF_SERVE_ENABLED` (default `false`: 403 `forbidden`) and the four caps are validated at startup with fail-fast bounds and change only by configuration and a restart. Migration `1791590400000_self_serve_servers` (additive): `servers.servers.created_via` (`operator` default, `self_serve`) and a deferred INSERT constraint trigger `servers_self_serve_has_owner` that refuses a self-serve server committed without an owner. An operator path that revives a removed self-serve id makes it `operator`. The managed list (`GET /api/servers/managed`) now shows operator-created agent servers only; the startup load still loads every one. `list-servers` prints `via=`. Runbook: `runbooks/agents.md`, "Self-serve servers".
