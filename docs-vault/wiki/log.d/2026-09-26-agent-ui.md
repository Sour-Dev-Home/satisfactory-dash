- 2026-09-26 — ADR-0031 PR 7, the agent UI: a "Game PC agent" section on Settings (`frontend/src/agent/`), per selected server and keyed by it. Every member sees how the backend reaches the server, whether an agent is enrolled, "Last seen N ago" (text only; an `online` badge follows once the backend adds that field) and the agent's version. Creating an enrolment code is for the operator on a server reached directly (the section says enrolling switches the server to the agent and forgets its stored tokens) and for an owner or admin on an agent server. The code is shown once, with its expiry, and lives only in the section's state: the mutation is not kept (`gcTime: 0`, `reset()` after copying) and a test asserts neither TanStack cache holds it. Revoking (owner or admin) asks first and says the server shows no data until an agent enrols again. The agent status polls every 30 s (`POLL_MS.agent`) only while the section is open. Demo: an enrolled agent, a made-up code, revoking refused. The shared package exports `EnrollmentCodeResponseSchema` but not its type, so the frontend infers it (a small follow-up for `packages/shared`).
