- 2026-10-25 — Update, compatibility and advisory banners (ADR-0057 Decision 7, build step 4). The dashboard compares each server's reported `agentVersion` with `GET /api/compat` and only informs; it never pushes an update or restarts anything. `frontend/src/updates/` holds `version.ts` (semver-ish compare tolerant of `+build` metadata, `versionInRange` for `<1.2.0` and `>=1.0.0 <1.2.3 || =2.0.0`; a malformed version or range gives no alarm), `notices.ts`, `UpdateBanners.tsx` and `dismissal.ts`. Which component a server runs comes from what the backend already stores (the mod reports `mod/x.y.z`, the agent a bare version), so there is no contract or backend change. Shell order: the "updating" notice first, then security advisories (alarm styling, not dismissible), an unsupported version (warning), and "Update available" (info, dismissible per release in localStorage, shown only when nothing stronger is). Agent: "restart the agent only" with a link to `runbooks/agent-app.md`; mod: "applies at the next server restart", Satisfactory Mod Manager wording, no URL. Also a line per agent server on the Servers page, a unit mock (quiet policy), `update-*` scenarios and a demo agent one release behind.
