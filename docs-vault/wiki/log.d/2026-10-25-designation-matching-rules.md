- 2026-10-25 — ADR-0055 PR 9 follow-up (matching rules, owner-approved): Planner designation matching in `map/services/designationMatching.ts` now runs in passes over every designation, oldest first: building id (only when the live building has the same class, else the id is stale), then exact class and position, then the nearest free building of the class within 2 m. A member whose position match would land on a held building takes the next free one in range; only with none is it missing and `claimedBy` reported. The result no longer depends on member order. Write overlap (`findOverlap`) compares ids only when both members have one, so two different ids never overlap; class and position are used only when a side has no id. Header comment of `packages/shared/src/plannerDesignations.ts` updated; no schema changes.
