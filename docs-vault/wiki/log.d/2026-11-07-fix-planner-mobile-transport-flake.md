- 2026-11-07 — The flaky phone run of the planner's transport-motion e2e test (`e2e/planner-graph.spec.ts`, "shows every transport mode as a glyph, moves them, and the Motion toggle stops them and is remembered") is fixed in the test; the app was right.
  - Seen four times since 2026-11-05 on main and unrelated PRs (e2e runs 42128032623, 42315267609, 42342847271 attempt 1, 42394170169), each time both attempts: `expect.poll(() => layerMotion.count()).toBeGreaterThanOrEqual(1)` received 0 at the mobile project.
  - Cause: only a lit transport whose route meets the settled view moves. On a 390 px phone the Iron Plate factory fits at the zoom floor (0.8), anchored left, so the fitted view holds only the Miner's train (layout x 175 to 544), and that train is dimmed as "outside the home site" (ADR-0063 Decision 3, state 5). The depot, truck and drone lines lie past the canvas. So at the settled phone view no glyph moves, by design. The test passed only when its poll sampled the first render's view, which `useSettled` hands back at once and which is fitted to the 1000 x 600 fallback stage before the canvas is measured; that view holds the depot line, so for about 150 ms after the measure a glyph moved. The trace of run 42394170169 confirms it: view `translate(16 34.2) scale(0.8)` on a 316 x 198 stage, the train's double line `data-dim`, the march layer present with no `animateMotion`.
  - Fix: the test focuses the graph viewport and zooms out (Minus, ten times) before the poll, so lit transports are in the settled view on every project and the poll waits for a state that holds rather than one that passes.
