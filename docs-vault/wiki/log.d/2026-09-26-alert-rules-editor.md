- 2026-09-26 — ADR-0027 PR 9b, the alert rules editor (`frontend/src/alerts/rules/`), presentational: `RulesEditor({ rules, items, canEdit, onCreate, onUpdate, onDelete })` never fetches; the page (9c) wires it. One card per rule, named by kind (an unknown kind keeps its own name and only its common fields); the enabled switch, severity (an unknown one kept as it is unless changed), and fire/clear/repeat edited in minutes and sent as whole seconds, with the contract's bounds checked after rounding (half a minute of repeat is refused). Per kind: stopped machines' threshold, the unreachable check's polls and minimum (in minutes), a production target's target in its item's unit and its 5–60 min window, with the item read-only ("delete and create to change it"). Save sends only what changed, validated with `UpdateAlertRuleRequestSchema`; the draft survives a failed save. Presets say they can be turned off, not deleted; other rules delete behind an inline confirm. A "New production target" form sends the item, target and window (severity only if changed) and lets the contract's defaults fill the timing. Without `canEdit` every setting shows as text under the same labels. Field errors replace the field's hint, tied with aria-describedby and aria-invalid. The kind and severity labels are local until 9a's `alertText.ts` lands (a TODO marks them).
