- 2026-09-26 — CI (ADR-0032 step 4): new scheduled workflow `.github/workflows/latency-probe.yml`. Twice an hour (and on demand) it requests `https://api.satis-manager.com/api/health/ready` once with curl and writes the status, DNS, TCP, TLS, first-byte and total times to the job summary (no response body). It fails only when the endpoint answers 200 but the total is over 2 seconds; a backend that is down (a failed request or a non-200) warns and stays green, because the backend runs on a PC that is often off and downtime alerting belongs to the external uptime monitor (ADR-0028), so a red run means "slow". It has `permissions: {}`, no checkout and no secrets, and reads only the public readiness endpoint.
