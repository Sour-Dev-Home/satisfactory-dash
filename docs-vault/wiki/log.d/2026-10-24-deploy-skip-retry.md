- 2026-10-24 — ADR-0054 PR 1 (deploy skip and pull retry). "Backend images" now stamps both images with `dev.satis-manager.inputs`, a SHA-256 over the git tree ids (with mode and type) of exactly what `backend/Dockerfile` builds from: `backend` (which holds the Dockerfile, its `Dockerfile.dockerignore`, the migrations and the CA bundle), `packages/shared`, `packages/game-adapter`, `package.json`, `package-lock.json`, and a root `.dockerignore` hashed as absent (new `scripts/deploy/inputs.mjs`). The release record keeps `inputs` (and `previous.inputs`); the automatic run skips staging and production with a "nothing deployable changed" summary when the newest images' hash equals the release's. A record or image without a valid hash never matches, a required input missing from the commit fails the hash, dispatched deploy, redeploy and rollback never skip, and a rollback records the inputs of the release it goes back to. `inputs.test.mjs` parses every non-`--from` `COPY`/`ADD` source of `backend/Dockerfile` and fails if one is outside the hashed paths. Staging now starts its task once more, 30 s later, when it stops with `CannotPullContainerError` (ADR-0054 D2); any other stop or a second pull failure fails as before; the staging job's timeout goes from 25 to 30 minutes to fit two attempts. Provenance attestation and action pins unchanged.
