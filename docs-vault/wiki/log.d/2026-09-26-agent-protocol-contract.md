- 2026-09-26 — ADR-0031 PR 3, the edge agent's protocol contract in `packages/shared` (schemas, endpoints, fixtures, contract tests; NO routes, so nothing is served yet). New `src/agent.ts`. The AGENT API lives under `/agent/v1`, not `/api/servers`, and is authenticated by the agent's own credential (`enroll` by the one-time code): `POST /enroll` (strict `{ code: /^[A-Z2-7]{4}-[A-Z2-7]{4}$/, agentVersion ≤ 32 }`, so no hostname or other machine detail can be sent, answers 201 `{ agentSecret, serverId, cadence }`), `POST /snapshots` (strict `{ agentVersion, observedAt with an offset, reachable, paused | null, status?, power?, factory?, players? }`, the parts REUSE the live routes' data schemas, and `reachable: false` allows no parts; answers `{ cadence, commandsPending }`), `GET /commands?waitSeconds=0..25` (a long-poll; `{ commands }` of `{ id, type, params, expiresAt }`, with a typed strict `SetAutoPauseParams`) and `POST /commands/:commandId/result` (strict `{ ok, code? }`, code from a closed list, a success carries none; answers `{ accepted: true }`). `Cadence` is three whole-second intervals from 1 to 3600. USER-facing, server-scoped: `POST /agent/enrollment-codes` (201, 10 minutes, single use), `GET /agent`, `DELETE /agent`, `GET /commands/:commandId` (a `Command` with status pending, sent, succeeded, failed or expired). The auto-pause PUT's response schema is now the union of today's 200 (the setting) and an additive 202 `{ command }`; the backend still sends 200 until PR 5, and the frontend's `AutoPauseView` re-reads the setting instead of caching a command. Deploy skew: response fields naming types, statuses, kinds and codes are plain strings (an OLD agent survives a NEWER backend), requests are strict. Four error codes (`enrollment_code_invalid` 400, `agent_outdated` 426, `command_not_found` 404, `command_expired` 409); an agent's auth failure, revoked or unknown alike, is the existing `unauthorized`. Both exhaustive code maps are updated (the backend's HTTP status map and the frontend's error-kind map). The body limits (gzip, a decompressed maximum) are documented in the contract for PR 5 to enforce. The backend's generated authorization tests exempt exactly the four user-facing agent routes until PR 5 mounts them, and a guard test fails the moment any is mounted, until the exemption is deleted. Fixtures: enrolment, a full, a partial and an unreachable snapshot, a commands list with `set_auto_pause` and one unknown type, results, agent status enrolled, silent and not enrolled, a command in every status, both auto-pause answers, and one error fixture per new code; contract tests pin the code alphabet, strictness (no machine details), the cadence and wait bounds, the offset times, deploy-skew tolerance and the endpoint table.
