- 2026-09-26 — ADR-0027 PR 5c, the alert kind `production_below_target` (amendment 3, approved by the owner; appended byte-identical to ADR-0027). Additive migration `1790812800000_alert_production_kind` widens the `alerts.rules.kind` CHECK (a deploy needs `db:migrate` first). `rules.ts`: the kind, its strict zod params (`item` class name, `targetPerMinute` above 0, `windowMinutes` 5 to 60, default 10), timing defaults (`for` 10 min, clear 5 min, repeat 1 h), and NO seeded preset (opt-in per item; rules come from the rules API in PR 7). The `ObservationBoard` factory observation gains `itemRates` (the factory-wide current rate per item), published by the factory poller from the same `sumItemRates` figures it records to history. `ServerAlertEvaluator` keeps a per-rule rolling window of those rates in memory (one sample per reading, no database reads in the tick): the condition is the window average below 90% of the target, cleared above 95% (`belowWithHysteresis`, so 92% never flaps). The window must be FULL (within one poll interval of the window size) before it decides; until then the answer is "unknown" and a firing alert holds. It restarts empty after a restart, a pause, an unreachable or muted stretch, a stale or after-resume reading, a change of game session, or a changed window size or item. An item nobody makes is a rate of 0 and fires. Paused and unreachable suppress it like the other kinds. `alertMessage.ts` words it ("Production below target: <item>", the average against the target, "still below target", "back on target"), the item escaped as game text. Tests: the evaluator (fill, no flap at 92%, exactly 90%, clear above 95%, restart, pause, unreachable, after-resume, stale, session change, mute, uncommitted, two items, window change), the params, the message, the poller's `itemRates`, and a real-Postgres test (CI only) for the CHECK. `runbooks/alerts.md` documents it.
